# Add a new module

1. Confirm a real capability gap and product approval for the module.
2. Choose a meaningful mythological name under `.agents/rules/naming.md`.
3. Define a descriptive stable technical module ID and typed contract.
4. Implement the smallest useful analysis path with shared findings and budgets.
5. Add offline fixtures and evaluation cases, including expected non-findings.
6. Expose through CLI; integrate with GitHub only after local validation.
7. Document usage, limitations, supported languages, and actual evaluation results.
